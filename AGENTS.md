# dio-agent — Living Telegram Agent

Постоянный AI-персонаж в Telegram: память, настроение, отношения, избирательная инициатива.
Go · PostgreSQL (+pgvector) · событийное ядро ago (github.com/luckystrker/ago, v0.6.0) · один процесс (бинарник) на VPS · systemd.

## Как работаем (пайплайн)

1. **Требования неясны** → скилл `grilling` (один вопрос за раз, с вариантами).
2. **Взять работу** → пункт из `CHECKLIST.md`; если пункт размыт — сначала гриллинг по нему.
3. **Перед реализацией** → убедиться, что решение не противоречит `PHILOSOPHY.md`, термины совпадают со словарём. Пункт должен идти тест-первым — скилл `tdd`.
4. **Нужно что-то изучить** → скилл `research` (фоновый агент, находки со ссылками в `docs/research/`).
5. **После реализации** → скилл `acceptance` (тестировщик → критик → гейт), только затем commit. Ревью большого диффа/ветки от точки — скилл `code-review`.
6. **Коммит** → хук-гейт `.zcode/hooks/pre-commit-gate.mjs` прогоняет gofmt/go vet/go test (юниты); коммит блокируется при красном.
7. **Конец сессии** → скилл `handoff`.

## Немного правил (весь список)

- Отметил пункт чек-листа — `[x]` в `CHECKLIST.md` в том же коммите.
- Изменил принятое решение — комментарий в начале изменённого документа-спецификации (дата, что, почему).
- Новое требование — в бэклог чек-листа, не молча в код.
- Гейты `gofmt`/`go vet`/`go test` не требуют живой БД: БД-зависимые тесты — `scripts/test-db.sh` (сам поднимает эфемерный PostgreSQL 17 + pgvector на свободном порту и удаляет его; боевая база 5433/dio_go не трогается), вне гейта.
- Один файл — одна ответственность; без необходимости не трогай модули вне текущего пункта чек-листа.
