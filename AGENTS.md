# dio-agent — Living Telegram Agent

Постоянный AI-персонаж в Telegram: память, настроение, отношения, избирательная инициатива.
TypeScript · PostgreSQL (+pgvector) · один процесс на VPS · systemd.

## Как работаем (пайплайн)

1. **Требования неясны** → скилл `grilling` (один вопрос за раз, с вариантами).
2. **Взять работу** → пункт из `CHECKLIST.md`; если пункт размыт — сначала гриллинг по нему.
3. **Перед реализацией** → убедиться, что решение не противоречит `PHILOSOPHY.md`, термины совпадают со словарём.
4. **После реализации** → скилл `acceptance` (тестировщик → критик → гейт), только затем commit.
5. **Коммит** → хук-гейт `.zcode/hooks/pre-commit-gate.mjs` прогоняет lint/typecheck/test; коммит блокируется при красном.
6. **Конец сессии** → скилл `handoff`.

## Немного правил (весь список)

- Отметил пункт чек-листа — `[x]` в `CHECKLIST.md` в том же коммите.
- Изменил принятое решение — комментарий в начале изменённого документа-спецификации (дата, что, почему).
- Новое требование — в бэклог чек-листа, не молча в код.
- Скрипты `test`/`lint`/`typecheck` не требуют живой БД: БД-зависимые тесты — отдельным скриптом вне гейта.
- Один файл — одна ответственность; без необходимости не трогай модули вне текущего пункта чек-листа.
