- Инцидент процесса приёмки: критик, делая временные мутации на незакоммиченном дереве, потерял правки через git checkout — перед ручными мутациями дерево коммитить/стейджить; раннер test:mutation от этого защищён (восстановление из памяти, не из git).
- Привязка work_items к чату (scopeId): порядок «позднее прямое не раньше значимого предшествующего batch того же чата» (§5.2) без неё невозможен — приносится этапом 2 вместе с turns.
- budget_reservations: поле pool и раздельные пулы с общим потолком (§16, §18) — когда появится второй потребитель бюджета, кроме планировщика.
- Детерминированные operation_id для retry-резервирования бюджета: сейчас миллисекундная гранулярность защищает только от дублей одного такта (находка цикла приёмки этапа 1).
- In-process retry закрытия буфера: при transient-сбое createTurn события остаются pending до рестарта (recoverStalePending) — добавить повторную попытку в живом процессе (находка Н4 цикла приёмки этапа 2).
- Решение по окну «пассивная группа» (§6.2): prefilter этапа 2 отправляет пассивный шум в journal_only, окно недостижимо — оставить для будущей «значимости группового обсуждения» или убрать; зафиксировать при этапе 4 (находка Н5).
- §13.3 перед отправкой: проверки mute/прав/deletion revision отсутствуют (реализована только проверка новых сообщений) + typing-индикаторы (каждые ~4 с) — этап 4/6 (находка Н6).
- §15 exploration MVP — «думающий» вызов модели без web-инструментов: интеграция search/fetch с fetch-layer безопасностью (SSRF-защита, лимиты 2 поиска/3 fetch) — отдельный этап перед автономностью.
- Quiet hours §14.3 (timezone чата) — не реализованы; задаются настройкой чата на этапе 6.
- Инициативы в группы выключены по умолчанию (§14.3) — включение настройкой чата на этапе 6.
- Статус failed/skipped для turns (§11.3): после исчерпания попыток turn навсегда остаётся result_ready; «отравлённый» validated_result роняет каждую попытку — нужен терминальный статус хода.
- Исчерпание дневного бюджета моделей сейчас терминально пропускает ход (SkipWorkError); честнее — отложенное возобновление на следующий день (next_attempt_at = завтра).
